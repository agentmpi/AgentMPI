## Introduction

The emergence of Large Language Models (LLMs) has catalyzed a fundamental shift in how autonomous agents operate, creating new opportunities for sophisticated multi-agent systems that can collaborate across diverse computing environments. However, the current landscape of agent development is characterized by fragmentation, with different frameworks employing incompatible communication patterns, security models, and integration approaches. This survey paper addresses a critical gap in the rapidly evolving field of AI agent interoperability by providing the first comprehensive analysis of four emerging standardization protocols designed to enable seamless communication between LLM-powered agents.

Figure 1: Historical evolution of agent communication protocols, showing the progression from early academic standards (KQML, FIPA-ACL) through enterprise integration patterns to modern LLM-era protocols. The timeline illustrates how agent communication has evolved from complex semantic frameworks to more practical, web-native approaches designed for contemporary AI systems.

The authors examine four distinct protocols that have emerged within just the past year: the Model Context Protocol (MCP) from Anthropic, the Agent Communication Protocol (ACP) from IBM, Google's Agent-to-Agent Protocol (A2A), and the open-source Agent Network Protocol (ANP). Each protocol addresses different aspects of the interoperability challenge, from basic tool invocation to decentralized agent marketplaces, representing a spectrum of approaches to solving the fundamental problem of how AI agents discover, authenticate, and collaborate with one another.

This research provides essential guidance for a field where standardization efforts are still nascent but critically important for the future scalability and security of autonomous AI systems. By analyzing these protocols through a structured lens of architecture, security, lifecycle management, and practical deployment considerations, the survey offers both immediate practical value and longer-term strategic insights for the development of interoperable agent ecosystems.

## Protocol Architectures and Core Components

The four protocols examined in this survey each adopt fundamentally different architectural approaches to agent communication, reflecting diverse design philosophies and intended use cases.

### Model Context Protocol (MCP)

MCP employs a client-server architecture built on JSON-RPC 2.0, functioning as what Anthropic describes as "USB-C for AI." The protocol defines four core capabilities that standardize how applications deliver context to LLMs:

- Tools: Model-controlled invocation of external APIs through structured function calls
- Resources: Application-controlled contextual data (files, database entries, live content)
- Prompts: User-controlled reusable templates for standardized AI interactions
- Sampling: Server-controlled delegation of LLM completion generation

The MCP architecture supports both local (stdio) and remote (HTTP with Server-Sent Events) transport mechanisms. The client initiates tool requests, while the server manages resource access and prompt templates. This asymmetric design optimizes for the common pattern where LLMs need to access external tools and data sources in a controlled manner.

### Agent Communication Protocol (ACP)

ACP implements a brokered client-server model with RESTful HTTP interfaces, designed for general-purpose agent communication across heterogeneous systems. The architecture centers around three key components:

- Agent Detail & Discovery Mechanism: Runtime APIs and manifest-based metadata (`.well-known/agent.yml`) for dynamic agent discovery
- Message Parser: Handles MIME-typed multipart messages supporting both binary and text content
- Policy Engine: Enforces access control and routing decisions based on configurable policies

The protocol supports both synchronous request-response and asynchronous messaging patterns, with session management enabling stateful interactions. ACP's registry-based discovery allows agents to advertise capabilities and locate relevant peers through structured metadata queries.

### Agent-to-Agent Protocol (A2A)

A2A adopts a peer-to-peer task delegation model optimized for enterprise collaboration scenarios. The protocol's architecture revolves around five core components:

- Agent Cards: Self-descriptive metadata containing name, capabilities, version, and skill definitions
- Skills: Atomic, actionable capabilities that agents can advertise and invoke
- Tasks: Units of work with defined inputs, outputs, and execution contexts
- Messages: Communication channels supporting JSON-RPC 2.0 over HTTP, SSE, and push notifications
- Artifacts: Structured outputs from skill execution that can be shared between agents

The protocol enables sophisticated inter-agent negotiation through Agent Card exchanges, allowing agents to discover complementary capabilities and coordinate complex workflows within trusted organizational boundaries.

### Agent Network Protocol (ANP)

ANP implements a fully decentralized peer-to-peer architecture designed for open internet agent collaboration. The protocol is structured in three distinct layers:

Application Protocol Layer:

- Agent Description in JSON-LD format for semantic self-description
- Agent Discovery through`.well-known/agent-descriptions` endpoints
- Agent Protocol Manager for interface negotiation

Meta Protocol Layer:

- Protocol Negotiation for dynamic compatibility resolution
- Protocol Debugging and Testing utilities

Identity and Encrypted Communication Layer:

- W3C Decentralized Identifiers (DIDs) for trustless identity verification
- End-to-end encryption for secure communication

ANP's architecture enables agents to discover peers through decentralized search engines, authenticate using cryptographic DIDs, and dynamically negotiate communication protocols without central coordination.

## Security Models and Lifecycle Management

Each protocol addresses security challenges through distinct approaches tailored to their architectural models and deployment scenarios. The authors provide a systematic analysis of security considerations across four lifecycle phases: Creation, Operation, Update, and Termination.

### MCP Security Framework

MCP addresses several critical security vulnerabilities in LLM-tool integration:

Tool Poisoning Mitigation: Schema validation ensures that tools conform to expected interfaces, preventing malicious tools from masquerading as legitimate APIs. The protocol implements strict type checking and parameter validation to detect anomalous tool behavior.

Credential Management: Token scoping limits the permissions available to individual tools, implementing the principle of least privilege. Credentials are managed through secure token exchange rather than direct secret sharing.

Sandbox Isolation: Runtime isolation through syscall filters and containerization prevents tools from accessing unauthorized system resources or escaping their execution environment.

### ACP Security Architecture

ACP implements a comprehensive security model addressing enterprise-grade requirements:

Message Integrity: JSON Web Signatures (JWS) ensure message authenticity and detect tampering during transmission. All inter-agent communications are cryptographically signed to maintain audit trails.

Authentication Framework: Integration with Role-Based Access Control (RBAC) systems and support for Decentralized Identifiers enables flexible authentication strategies suitable for different organizational contexts.

Transport Security: Mandatory TLS encryption for all communications, with additional support for capability-scoped tokens that limit agent permissions based on specific interaction contexts.

### A2A Security Considerations

A2A focuses on securing collaborative workflows within organizational trust boundaries:

Agent Card Verification: Digital signatures prevent Agent Card spoofing, ensuring that capability advertisements are authentic and haven't been tampered with during transmission.

Task Injection Prevention: Input validation and sanitization protect against malicious task payloads that could compromise agent execution environments.

Notification Security: Push notification channels implement authentication and encryption to prevent message interception or replay attacks.

### ANP Trustless Security Model

ANP's decentralized architecture requires robust security without centralized trust authorities:

DID-based Authentication: W3C Decentralized Identifiers provide cryptographic identity verification without requiring certificate authorities or centralized identity providers.

Interface Integrity: Cryptographic signing of interface descriptions prevents protocol tampering and ensures that agent capabilities are accurately represented.

Privacy Preservation: End-to-end encryption ensures that sensitive communications remain confidential even when routed through untrusted intermediaries.

## Comparative Analysis and Trade-offs

The systematic comparison of these four protocols reveals fundamental trade-offs between simplicity, security, and scalability that organizations must consider when selecting appropriate standards for their use cases.

| Dimension | MCP | ACP | A2A | ANP |
| --- | --- | --- | --- | --- |
| Architecture | Client-Server | Brokered Client-Server | Peer-to-Peer | Decentralized P2P |
| Discovery | Manual Configuration | Registry-based | Agent Card Exchange | Decentralized Search |
| Identity & Auth | Token-based | RBAC/DID Integration | Digital Signatures | W3C DID Native |
| Message Format | JSON-RPC | Multipart MIME | JSON-RPC + Artifacts | JSON-LD |
| Session Support | Stateless | Stateful Sessions | Task-based Sessions | Protocol Negotiation |
| Target Scope | LLM-Tool Integration | Cross-framework Agents | Enterprise Collaboration | Open Internet Markets |

Architectural Trade-offs: MCP's client-server model optimizes for simplicity and tight LLM integration but limits scalability for complex multi-agent scenarios. ACP's brokered architecture provides better load balancing and fault tolerance at the cost of central coordination overhead. A2A's peer-to-peer model enables direct agent collaboration but requires pre-established trust relationships. ANP's fully decentralized approach maximizes autonomy and resilience but introduces significant complexity in identity management and protocol negotiation.

Security vs. Usability: The protocols demonstrate a clear progression in security sophistication. MCP prioritizes ease of integration with basic token-based security suitable for trusted environments. ACP adds enterprise-grade authentication and encryption while maintaining REST familiarity. A2A introduces cryptographic verification for inter-organizational scenarios. ANP provides the highest security through trustless DID-based identity but requires the most complex setup and maintenance.

Scalability Considerations: Each protocol targets different scales of deployment. MCP excels in single-application contexts with limited tool sets. ACP supports medium-scale enterprise deployments with centralized governance. A2A handles complex collaborative workflows within organizational boundaries. ANP addresses internet-scale agent ecosystems but with higher operational complexity.

## Phased Adoption Roadmap

Based on the comparative analysis, the authors propose a strategic four-phase adoption roadmap that allows organizations to progressively build interoperability capabilities while managing complexity and risk.

### Phase 1: Foundation with MCP

Organizations should begin with MCP for establishing secure, standardized communication between LLMs and external tools. This phase focuses on:

- Implementing basic tool invocation patterns for existing AI applications
- Establishing security baselines for LLM-external system interactions
- Building organizational familiarity with structured agent protocols
- Creating reusable prompt templates and resource access patterns

MCP's simplicity makes it ideal for initial adoption, allowing teams to gain experience with agent interoperability concepts without complex infrastructure requirements.

### Phase 2: Cross-Framework Communication with ACP

The second phase introduces ACP to enable communication between different agent frameworks and platforms:

- Connecting agents built with different LLM frameworks (LangChain, LlamaIndex, etc.)
- Implementing multimodal messaging for complex data exchange
- Establishing agent registries for dynamic discovery within organizations
- Building stateful session management for longer-running collaborations

ACP's REST-native design leverages existing web infrastructure knowledge while adding agent-specific capabilities.

### Phase 3: Enterprise Collaboration with A2A

Phase three focuses on complex multi-agent workflows using A2A:

- Implementing Agent Card-based capability discovery
- Building task delegation and artifact sharing mechanisms
- Establishing trust relationships for inter-departmental agent collaboration
- Creating workflow orchestration for multi-step agent processes

A2A enables sophisticated coordination patterns while maintaining security within organizational boundaries.

### Phase 4: Open Ecosystem Participation with ANP

The final phase extends interoperability to the open internet using ANP:

- Implementing DID-based identity for trustless authentication
- Participating in decentralized agent marketplaces
- Building protocol negotiation capabilities for maximum compatibility
- Contributing to open-source agent ecosystem development

ANP represents the ultimate vision of fully interoperable agent ecosystems but requires significant technical sophistication.

## Significance and Future Directions

This survey addresses a critical inflection point in the evolution of autonomous AI systems. As LLM-powered agents become increasingly prevalent across industries, the lack of standardized communication protocols represents a fundamental barrier to realizing their full potential. The systematic analysis provided here offers several key contributions to the field.

The comparative framework developed by the authors provides a structured approach for evaluating agent interoperability solutions, enabling researchers and practitioners to make informed decisions based on their specific requirements and constraints. This framework extends beyond the four protocols examined, offering a template for analyzing future standards as they emerge.

The security analysis reveals important patterns in how different architectural approaches address trust, authentication, and communication integrity. These insights are particularly valuable as organizations deploy agents in increasingly sensitive and mission-critical contexts where security failures could have significant consequences.

The proposed adoption roadmap offers practical guidance for organizations navigating the transition from fragmented, custom integration approaches to standardized, interoperable agent ecosystems. By providing a phased approach, the roadmap reduces the risk and complexity associated with adopting multiple emerging standards.

Looking toward future research directions, the survey identifies several critical areas requiring continued investigation. Protocol interoperability bridges will be essential for enabling communication between agents using different standards. Trust frameworks for cross-organizational agent collaboration need further development, particularly in establishing reputation systems and dispute resolution mechanisms. Standardized evaluation benchmarks for agent interoperability protocols will help the community assess and compare different approaches objectively.

The timing of this survey is particularly significant given the rapid pace of development in the LLM agent space. By documenting and analyzing these early standardization efforts, the work provides a historical record and analytical foundation that will inform future protocol development and adoption decisions. As the field matures, the insights provided here will help ensure that interoperability remains a central consideration in the design of next-generation autonomous agent systems.
