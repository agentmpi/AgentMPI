###### Abstract

The reduce-scatter collective operation in which p𝑝pitalic_p processors in a network of processors collectively reduce p𝑝pitalic_p input vectors into a result vector that is partitioned over the processors is important both in its own right and as building block for other collective operations. We present a surprisingly simple, but non-trivial algorithm for solving this problem optimally in ⌈log2⁡p⌉subscript2𝑝\lceil\log_{2}p\rceil⌈ roman_log start_POSTSUBSCRIPT 2 end_POSTSUBSCRIPT italic_p ⌉ communication rounds with each process sending, receiving and reducing exactly p−1𝑝1p-1italic_p - 1 blocks of vector elements. We combine this with a similarly simple allgather algorithm to get a likewise optimal algorithm for the allreduce collective operation where the result vector is replicated on all processors. The communication pattern is a simple, ⌈log2⁡p⌉subscript2𝑝\lceil\log_{2}p\rceil⌈ roman_log start_POSTSUBSCRIPT 2 end_POSTSUBSCRIPT italic_p ⌉-regular, circulant graph also used elsewhere. The algorithms assume the binary reduction operator to be commutative and we discuss this assumption. The algorithms can readily be implemented and used for the collective operations MPI_Reduce_scatter_block, MPI_Reduce_scatter and MPI_Allreduce as specified in the MPI standard. The communication pattern can likewise be used for all-to-all communication.

## 1 Introduction

By the associativity of ⊕direct-sum\oplus⊕, brackets can be left out. If the operator is also commutative, the order of the input vectors does not matter. The result vector W𝑊Witalic_W can be stored at either a designated root processor, at all processors, or be partitioned into p𝑝pitalic_p blocks of elements with block W⁢[r]𝑊delimited-[]𝑟W[r]italic_W [ italic_r ] of the result stored at processor r𝑟ritalic_r. Blocks may have the same or different numbers of vector elements. These problems are solved by the MPI collectives MPI_Reduce (reduction to a designated root process), MPI_Allreduce (result vector replicated on all processes) , MPI_Reduce_scatter_block (block partitioned reduction with all vector result blocks having exactly the same number of elements) and MPI_Reduce_scatter (block partitioned reduction with possibly different vector block sizes) [10]. The commonly used term reduce-scatter is somewhat unfortunate, since it suggests that the problem is solved in two stages as a reduction to a root processor followed by a scatter operation for partitioning the result vector. Good algorithms work differently. A better intuition is to view the operation as p𝑝pitalic_p simultaneous, rooted reductions with each processor r𝑟ritalic_r being the root in a reduction of the blocks with index r𝑟ritalic_r. The reduce-scatter algorithm to be presented in the following follows this intuition, but the processors cooperate subtly in the reduction of the blocks. We will alternatively refer to the reduce-scatter operation as block-reduce.

Our algorithms work uniformly for any number of processors p𝑝pitalic_p. We assume the operator ⊕direct-sum\oplus⊕ to be commutative. The processors communicate in a ⌈log2⌉subscript2\lceil\log_{2}\rceil⌈ roman_log start_POSTSUBSCRIPT 2 end_POSTSUBSCRIPT ⌉-regular circulant graph pattern where each processor has ⌈log2⁡p⌉subscript2𝑝\lceil\log_{2}p\rceil⌈ roman_log start_POSTSUBSCRIPT 2 end_POSTSUBSCRIPT italic_p ⌉ incoming and ⌈log2⁡p⌉subscript2𝑝\lceil\log_{2}p\rceil⌈ roman_log start_POSTSUBSCRIPT 2 end_POSTSUBSCRIPT italic_p ⌉ outgoing neighbors. Communication is assumed to be only one-ported (a processor can be engaged in one communication operation at a time), but fully bidirectional, and can readily be implemented with the combined MPI_Sendrecv operation of MPI [10].

The reduce-scatter (block-reduce) and allreduce operations have been intensively researched and many algorithms and implementations, taking aspects of the communication system (different topologies, different, hierarchical organizations) into account have been proposed. A primary starting point for the algorithms of this paper is the well known and often used power-of-two, straight doubling, circulant graph, dissemination allgather (concatenation, all-to-all broadcast) algorithm by Bruck et al. [7]. The algorithms by Bar-Noy and others for allreduce (computing census functions) [1, 6] that use a cleverly adjusted doubling scheme have likewise been a starting point for subsequent algorithms and generalizations, both for the allreduce and for the reduce-scatter operation [4, 17].

Well-known algorithms assuming either a ring or fully connected communication network can solve the problem in p−1𝑝1p-1italic_p - 1 communication rounds, in which each processor sends and receives a partial block result W⁢[i]𝑊delimited-[]𝑖W[i]italic_W [ italic_i ] to and from a preceding and a succeeding processor and performs a reduction on the received partial result block, see for instance [8, 9]. With a ring, the ⊕direct-sum\oplus⊕ operator must be commutative whereas with a fully connected network, the algorithm can also work for non-commutative operators [9]. These algorithms are optimal in the number of blocks that are sent and received per processor, namely p−1𝑝1p-1italic_p - 1, but have a linear number of communication rounds which is very unattractive for large number of processors p𝑝pitalic_p. The lower bound on the number of communication rounds is obviously ⌈log2⁡p⌉subscript2𝑝\lceil\log_{2}p\rceil⌈ roman_log start_POSTSUBSCRIPT 2 end_POSTSUBSCRIPT italic_p ⌉.

The reduce-scatter problem can be solved in log2⁡psubscript2𝑝\log_{2}proman_log start_POSTSUBSCRIPT 2 end_POSTSUBSCRIPT italic_p communication rounds with the optimal number p−1𝑝1p-1italic_p - 1 of sent, received and reduced partial result blocks with a log2⁡psubscript2𝑝\log_{2}proman_log start_POSTSUBSCRIPT 2 end_POSTSUBSCRIPT italic_p-dimensional hypercube or butterfly communication pattern. Likewise, the allreduce problem can be solved with twice as many communication rounds and send-receive operations. A drawback of these simple algorithms is that they do not readily extend to arbitrary numbers of processors (not only powers-of-two). This problem has often been addressed and extensions that are better than the trivial reduction to the nearest power-of-two have been proposed and implemented [12, 14]. Hypercube or butterfly pattern algorithms with some care work also for non-commutative operators.

For the reduce (reduction to root) and allreduce operations, pipelined fixed-degree (binary) trees are also used. Such algorithms are simple to implement and can work for any number of processors, sometimes also for non-commutative operators (depending on how trees are numbered), but have the disadvantage of loosing effective bandwidth proportional to the arity of the trees. Likewise, there is a latency penalty proportional to the size of the pipeline block size, which can in addition be difficult to select well. Some of these problems can be alleviated [13].

A standard observation is that allreduce can be accomplished by performing a reduce-scatter (block-reduce) operation followed by an allgather operation. Lower bound arguments in [11, 2] show that when the total number p⁢(p−1)𝑝𝑝1p(p-1)italic_p ( italic_p - 1 ) of required applications of the ⊕direct-sum\oplus⊕ operator to blocks of elements are evenly shared by the processors, it is required to send and receive 2⁢(p−1)2𝑝12(p-1)2 ( italic_p - 1 ) blocks per processor. Using the reduce-scatter (block-reduce) and allgather algorithm of the present paper, the bound on the number of blocks is achieved with 2⁢⌈log2⁡p⌉2subscript2𝑝2\lceil\log_{2}p\rceil2 ⌈ roman_log start_POSTSUBSCRIPT 2 end_POSTSUBSCRIPT italic_p ⌉ communication rounds.

## 3 Implementation in and for MPI

Both Algorithm 1 and 2 can readily be implemented in MPI [10] with MPI_Sendrecv or MPI_Isendrecv for the bidirectional, combined Send⁢()∥Recv⁢()conditionalSendRecv\textsf{Send}()\parallel\textsf{Recv}()Send ( ) ∥ Recv ( ) operation. Standard considerations as when implementing the doubling allgather algorithm of Bruck et al. [7] apply, see for instance [5, 15]. In particular, the doubling and halving schemes lead to latency contention and communication redundancy when run as written on clustered, hierarchical systems with constrained per node bandwidth [16].

The algorithms compute the required skips in constant time per communication rounds. All partial result blocks are kept in consecutive buffers and no reordering of block is needed in the ⌈log2⁡p⌉subscript2𝑝\lceil\log_{2}p\rceil⌈ roman_log start_POSTSUBSCRIPT 2 end_POSTSUBSCRIPT italic_p ⌉ communication rounds. Reduction and copy operations can therefore be done as bulk operations over many blocks. A property of the roughly halving scheme is that no sequence of blocks is longer than ⌈p/2⌉𝑝2\lceil p/2\rceil⌈ italic_p / 2 ⌉. This can be exploited to avoid half of the copy operations [17]. The standard, straight doubling scheme does not have this property [7]. Explicit copying could be avoided altogether by using the derived datatype mechanism of MPI [10], as done for all-to-all algorithms in [18]; however, copying is done only before and after the communication rounds, and therefore this is not likely to be a fruitful implementation choice.

## 4 Summary

This paper gave a very simple and easily implementable algorithm for the reduce-scatter (block-reduce) operation as found in message-passing frameworks like MPI [10]. The algorithm is optimal in number of communication rounds and in communication and computation volume. The algorithm was used as building block of an allreduce algorithm that is likewise optimal in communication and computation volume.

The circulant graph communication patterns that were used for reduce-scatter (block-reduce) and allreduce, can, with some craft, also be used to solve the all-to-all communication problem in the same number of communication rounds, similarly to the straight doubling all-to-all (indexing) algorithms given in [7], namely by letting the ⊕direct-sum\oplus⊕ operator be concatenation of element blocks. By specialization of the algorithms, likewise algorithms for the rooted, regular scatter and gather problems can easily be derived (MPI_Scatter, MPI_Gather). We also indicated that the algorithms can be used for reduction to root (MPI_Reduce), and by implication, for broadcast (MPI_Bcast), and may be attractive for small problems. Circulant graphs are a universal scheme for collective operations as found in MPI and elsewhere [17].
